# Summarization SLM — brief
Status: ready
Updated: 2026-09-28

## Purpose
A personal learning project: build a small language model that "will excel at summarization of
texts" — research papers, news articles and general webpages — and in doing so master the full
pipeline end to end: gathering and cleaning a large free corpus into a database, training in
stages (pretrain / continued-pretrain → supervised fine-tuning → reinforcement learning from
judge-model scores), and validating each step with visual evidence that training is working.
The working summarizer is the proof; the understanding is the goal.

## Users and use
Just the user. Run through CLI scripts (ingest, train, hyperparameter search, evaluate), a
dashboard web UI for data and training progress, and a local summarize endpoint for trying a
trained model on a document. The first milestone is the data: a large, clean, fully built
database before any training work.

## Constraints
- Personal learning project; single user.
- Python + Postgres.
- Develop and smoke-test on the Mac (Apple Silicon); real training on rented cloud GPUs.
- The database (Postgres and raw files) lives on the Mac / an external disk; snapshots go to the GPU box for training.
- Corpus target: ~100–500 GB of cleaned text.
- Model size target: ~0.5B parameters (from-scratch path); open base models of similar size.
- Free data sources only; non-commercial / research-only licenses acceptable if recorded.
- Stage order: pretrain / continued-pretrain → supervised fine-tuning → judge-reward RL.
- Budget: judge / teacher API spend under $50/month; rented GPU $100–$300/month.
- Qwen judge is self-hosted on the rented GPU, not called through an API.
- Start clean: no earlier code carried forward.

## Success criteria
Milestones in order; data is first.
- **Data:** the database holds ≥100 GB of cleaned, deduplicated text from research papers, news and webpages, plus ≥500k document → summary pairs, every record with its source and license; a rendered data-validation report shows the checks passing.
- **Training:** both paths (from scratch and open base model) run every applicable stage through the single-run script; the hyperparameter-search script completes a sweep and reports the best config.
- **Quality:** on the held-out test set, the SFT model beats its base and the RL model beats the SFT model on judge score without losing factual consistency, shown in the visual report.

## Open questions

- Mac / external disk capacity for 100–500 GB of cleaned text plus raw originals — leaning: none (suggested: external disk).
- No OpenAI key yet — leaning: none (suggested: build the adapter; exercise it once a key exists).
- Whether ≥500k summary pairs and RL judging fit the $50/month API budget — leaning: none (suggested: self-hosted Qwen does the bulk; Anthropic within the cap).
- The RL algorithm: the user named PPO, but the intent is RL from judge scores — leaning: none (suggested: whatever works reliably with judge rewards).
